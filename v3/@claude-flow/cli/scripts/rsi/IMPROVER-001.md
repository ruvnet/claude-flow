# Minimal inherited improver contract

This increment adds a deterministic exposed-training ranker scaffold while
compatible OS isolation and repair-resource authorization remain unavailable. It
does not remove the executable-repair proposer blocker, admit a new empirical
hypothesis or execute repository repairs.

One deterministic child mechanism derives versioned diagnosis-rule, patch-family
and test-selection state. Five arms use the same proposer, training trace,
permissions and descriptor budget: inherited, frozen, static, shuffled and
previous optimizer. Each child emits two successor proposal descriptors and
scores them against the exposed p-limit training trace. No patch bytes are
generated or applied.

There is no prior repair optimizer at generation zero, so the `previous` state
is explicitly bound to the parent and degenerates with `frozen`; arm identity is
still included in every descriptor. This is a disclosed calibration limitation,
not an invented predecessor checkpoint.

The p-limit failure and published fix are calibration-only. Any apparent ranking
advantage on that trace is circular training fit, not fresh-task improvement,
descendant improvement capacity, independent evidence or RSI. A future reviewed
hypothesis must freeze fresh development tasks before any arm reads their outcomes.

The subprocess phase is limited to five child processes and ten descriptor scores.
The complete fifteen-test acceptance run computes 40 descriptor scores: 30
in-process assertions plus ten child-process results. In-process calls record zero
child starts; only the five spawned children record one each.
It consumes zero repair candidate evaluations, isolated starts, native field calls,
model calls or provider spend. The unapproved 36-evaluation repair proposal and
the original seven-epoch, 209784-call ledger are unchanged.
