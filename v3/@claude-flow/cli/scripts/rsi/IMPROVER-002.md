# Exposed-template patch materializer contract

This engineering increment removes one narrow blocker between ranked descriptors
and executable candidates: an inherited child can materialize a bounded,
content-addressed single-replacement patch artifact without post-spawn researcher
input. It does not apply the patch to a repository or execute a candidate.

The materializer consumes the reviewed inherited improver plan, the inherited
arm's top descriptor and the exact p-limit base `index.js` Git blob. A fixed
grammar wraps `limitFunction` and forwards `clearQueue`. The child receives no
known-fix fixture path. The child does read the exposed-fix-derived transformation
from the reviewed plan; direct fixture reads are not observed, not syscall-audited.
Its output binds the source Git blob and SHA-256, descriptor,
both plans, exact removal and insertion bytes, selected tests and resulting source
hash. In-memory replay must reconstruct the exact published fix blob.

This is not autonomous synthesis. The grammar was written from the exposed fix,
only the inherited arm has an admitted patch template, and the known fix is used
as a parent-side test oracle. Frozen, static, shuffled and previous controls cannot
borrow the template. Matched control patch coverage, fresh tasks, repository
execution and improvement-capacity measurement remain false.

One child materialization performs four training-only descriptor scores because
the child result is recomputed before trust, one bounded source read, one patch
artifact and one in-memory replacement. It consumes zero repair evaluations,
isolated starts, native calls, model calls or provider spend. The separate proposal
for 36 evaluations, 216 isolated starts and 1080000 summed process milliseconds
remains unapproved.
